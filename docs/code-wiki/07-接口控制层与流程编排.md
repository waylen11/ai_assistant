| 模块 | 方法+路径 | 权限 | 说明 |
|---|---|---|---|

## 7.2 重点 Controller 拆解

### 7.2.1 ChatController —— IP 探测小技巧

源码：[ChatController.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/controller/ChatController.java)

```java
@GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamChat(@RequestParam String message,
                               @RequestParam(required = false) String modelName,
                               HttpServletRequest request)
```

三个知识点：

1. **`produces = TEXT_EVENT_STREAM_VALUE`**：声明响应是 SSE 格式（`text/event-stream`），
   告诉浏览器"这是流，别等结束再渲染"。
2. **返回类型 `Flux<String>`**：响应式流 = 0..N 个字符串按时间逐个发出（WebFlux 的招牌）。
3. **getClientIp 代理链解析**：依次查 `X-Forwarded-For` → `Proxy-Client-IP` → `getRemoteAddr()`，
   多级代理取第一个逗号前地址。Nginx 反代场景下必须看转发头才能拿到真实 IP，
   否则所有用户都记成 127.0.0.1——**未登录用户的记忆就全串了**，这是个真实生产问题。

### 7.2.2 AuthController —— 登录四步验证

源码：[AuthController.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/controller/AuthController.java)

```java
// POST /auth/login
SysUser user = findByUsername(username).orElseThrow(用户名或密码错误);
if (!user.getEnabled()) return fail("账号已被禁用");                 // 禁用检查
if (!BCrypt.checkpw(clientHash, user.getPassword())) throw 用户名或密码错误;
StpUtil.login(user.getId(), new SaLoginModel().setExtra("username", ...));  // ★ 登录取token
user.setLastLoginAt(now);                                            // 顺手记登录时间
return LoginResponse(token=StpUtil.getTokenValue(), ... 三权限 ...);
```

安全细节：**用户名不存在和密码错误返回同一句话**（防用户枚举攻击）；返回体里带三权限布尔值，前端据此显示/隐藏菜单。

### 7.2.3 AssistantController —— 登录态取 userId

源码：[AssistantController.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/controller/AssistantController.java)

```java
Long userId = StpUtil.getLoginIdAsLong();   // 从 token 里解析出"我是谁"
```

`StpUtil.getLoginIdAsLong()` 是 Sa-Token 的核心 API：
在拦截器里 `StpUtil.login(id)` 存了登录态（JWT 里带 id），
之后任何接口都能用这一行拿到当前登录用户——**这就是无状态 JWT 的使用姿势**。

## 7.3 Sa-Token 鉴权全规则（再背一遍）

源码：[SaTokenConfig.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/config/SaTokenConfig.java)

```
请求进来
  │
  ├─ OPTIONS？─────────────────▶ 放行（CORS 预检）
  ├─ /chat/**, /auth/**, /models/enabled ─▶ 公开
  ├─ /admin/models/** ──▶ 登录 + permModel
  ├─ /admin/knowledge/** ──▶ 登录 + permKnowledge
  ├─ /admin/users/** ──▶ 登录 + permUser
  ├─ /assistant/** ──▶ 登录
  └─ 其余 /** ──▶ 登录
```

加上 `excludePathPatterns` 双保险（`/auth/login`、`/auth/salt/*`、`/chat/**`、`/models/enabled`、`/error`）。
两层防线：拦截器内 match 放行 + 拦截器外 exclude 不进——**即使 match 忘写，exclude 也兜住**。

登录态参数（application.yml）：

```yaml
sa-token:
  token-name: Authorization     # 前端 header 字段名
  timeout: 2592000              # 30 天
  is-concurrent: true           # 允许多端同时登录
  token-style: uuid             # token 随机
  jwt-secret-key: ...           # JWT 签名密钥（≥32位）
```

## 7.4 CustomerServiceGraph —— 客服流程编排

源码：[CustomerServiceGraph.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/graph/CustomerServiceGraph.java)

### 7.4.1 图长什么样（4 节点 4 边）

```
              ┌─────────────┐
              │  意图识别    │  (100,200)
              └──┬───────┬──┘
         知识查询│       │业务操作
                 ▼       ▼
        ┌────────────┐ ┌────────────┐
        │  知识检索   │ │  业务执行   │  (350,80 / 350,320)
        └─────┬──────┘ └─────┬──────┘
              │              │
              ▼              ▼
              ┌─────────────┐
              │  回复生成    │  (600,200)
              └─────────────┘
```

- `getGraphDefinition()`：把节点（id/type/label/x/y）和边（source/target/condition）组装成
  `GraphDefinitionDTO` 给前端画布渲染；
- 节点/边的所有名字都来自 `GraphConstants` 枚举——**前端画布和后端执行逻辑共用一套命名**，不会对不上。

### 7.4.2 execute —— 三段式执行

```java
public GraphExecutionResultDTO execute(String userInput, GraphContext context) {
    // Step1 意图识别（关键词规则）
    String intent = recognizeIntent(userInput);
    // Step2 按意图路由
    if ("knowledge".equals(intent)) retrievedContext = retrieveKnowledge(userInput);
    else if ("business".equals(intent)) retrievedContext = executeBusiness(userInput, context);
    // Step3 组装结果（回复生成交给上层 ChatService 的大模型）
    return result(intent, retrievedContext, nextAction = "reply_generation");
}
```

**关键词意图识别**（当前简化实现）：

```java
if (包含 预约/联系/采购/入库/出库/销售) return "business";  // 业务操作
return "knowledge";                                        // 默认走知识查询
```

### 7.4.3 诚实解读（面试时的正确话术）

这个类注释自己写了："**简化实现，生产环境使用 SpringAIAlibabaGraph StateGraph API**"。
当前 `retrieveKnowledge` / `executeBusiness` 返回空串，真实检索逻辑在 `KnowledgeService.retrieve`。
所以面试时可以这么讲：

> "流程编排层定义了 意图识别→知识检索/业务执行→回复生成 的标准客服流程，
> 用 Spring AI Alibaba Graph 的节点图模型表达；当前意图识别用关键词规则做轻量实现，
> 预留了接入 LLM 分类器与 StateGraph 状态机的演进空间——这是我后续的优化方向。"

**这样讲既真诚又体现思考**，比硬吹"我们用了最强图引擎"强一百倍（源码骗不了面试官）。
