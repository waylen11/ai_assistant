## 10.1 运行方式一：Docker Compose 一键部署（推荐）

编排文件：[docker-compose.yml](../../docker-compose.yml) ｜ 部署脚本：[deploy.ps1](../../../deploy.ps1)

### 六个容器全家桶

| 容器 | 镜像 | 端口 | 固定内网 IP | 作用 |
|---|---|---|---|---|
| aics-mysql | mysql:8.0 | 3306 | 172.20.0.10 | 主库（挂载 schema.sql 自动初始化） |
| aics-redis | redis:7.2-alpine | 6379 | 172.20.0.11 | 记忆/会话 |
| aics-minio | minio/minio | 9000/9001 | 172.20.0.12 | 对象存储（9001 是控制台） |
| aics-etcd | quay.io/coreos/etcd:v3.5.5 | — | 172.20.0.13 | Milvus 的元数据存储 |
| aics-milvus | milvusdb/milvus:v2.4.5 | 19530/9091 | 172.20.0.14 | 向量库（standalone 模式，依赖 etcd+minio） |
| aics-backend | 本项目 Dockerfile | 8080 | 172.20.0.20 | Spring Boot 后端 |
| aics-frontend | 前端 Dockerfile | 80 | 172.20.0.21 | Nginx 托管前端+反代 |

### 启动步骤

```powershell
# 1. 准备环境变量
cp .env.example .env        # 编辑填入 DASHSCOPE_API_KEY（必填）、JWT_SECRET_KEY（必填）

# 2. 一键启动
.\deploy.ps1 start          # Windows PowerShell
# Linux/macOS：docker compose up -d --build

# 3. 访问
# 前端 http://localhost   后端 http://localhost:8080   MinIO控制台 http://localhost:9001
# 默认账号 admin / admin123
```

### 编排文件中值得讲的工程细节

1. **healthcheck + depends_on(condition: service_healthy)**：MySQL/Redis/Milvus 健康检查通过后，后端才启动——解决"数据库还没就绪后端抢先启动连不上"的经典竞态；
2. **固定 IP 子网**：`172.20.0.0/16` 里每个服务固定 IP，服务间通过容器名互相访问（如 `jdbc:mysql://mysql:3306`）；
3. **MySQL 初始化自动化**：把 schema.sql 挂载到 `/docker-entrypoint-initdb.d/`，容器**首次**启动自动建库建表插种子数据；
4. **环境变量注入**：compose 的 `environment` 段落把 `.env` 的值转成 `SPRING_DATASOURCE_URL` 等后端认识的变量（application.yml 里 `${SPRING_DATASOURCE_URL:default}` 读取）；
5. **数据卷持久化**：mysql-data / redis-data / etcd-data 等 volume，容器删了数据还在。

### 后端 Dockerfile（多阶段构建）

[Dockerfile](../../ai-customer-service-backend/Dockerfile) 两阶段：

```dockerfile
# Stage1：maven:3.9.6-eclipse-temurin-17-alpine   —— 构建环境（大镜像）
#   先 COPY pom.xml + mvn dependency:go-offline    —— 利用 Docker 层缓存加速
#   再 COPY src + mvn package -DskipTests
# Stage2：eclipse-temurin:17-jre-alpine           —— 运行环境（瘦镜像，只有 JRE）
#   COPY --from=builder jar
#   非 root 用户运行（安全）
#   ENTRYPOINT java $JAVA_OPTS -jar app.jar
```

**"构建大镜像、运行小镜像"的这个套路**就是面试常说的"多阶段构建减小镜像体积"。

## 10.2 运行方式二：本地开发模式

```bash
# 前提：本地已装 Java17 / Maven / MySQL8 / Redis / MinIO / Milvus(可选)

# 1. 建库
mysql -u root -p < ai-customer-service-backend/src/main/resources/db/schema.sql

# 2. 改配置（application.yml 或 config.yml 或环境变量）
#    datasource.password = 你的MySQL密码
#    spring.ai.dashscope.api-key = sk-xxxx  （必填）
#    sa-token.jwt-secret-key = 任意32位以上

# 3. 启动后端
cd ai-customer-service-backend
mvn spring-boot:run
# 看到 "Started AiCustomerServiceApplication" 即成功

# 4. 验证（另开终端）
curl http://localhost:8080/api/models/enabled
```

## 10.4 常见坑与排查（FAQ）

### Q1：启动报 "Communications link failure"/连不上 MySQL
→ 检查 MySQL 是否存活；本地跑注意密码、`allowPublicKeyRetrieval=true`。

### Q2：后端容器一直 unhealthy
→ 编排里健康检查 URL 是 `/actuator/health`，但 pom.xml **没有引入 spring-boot-starter-actuator**，
   该端点会 404。这是一个已知缺口——你可以说"我发现了这个问题，计划补充 actuator 依赖或改用 /api/models/enabled 探活"（标准面试改进素材）。

### Q3：上传文档后 vector_status 一直是 pending/processing 或变 failed
→ 检查 Milvus 是否可达；确认 `SPRING_AI_DASHSCOPE_API_KEY` 有效（Embedding 也走它）；看 error_msg 字段。

### Q4：聊天/检索完全用不上知识库（检索返回空）
→ **默认 `spring.ai.vectorstore.milvus.enabled=false`（dummy 空实现）**。
  完整 RAG：改成 `true` + Milvus 部署 + Embedding Key 可用。

### Q5：登录报 403 / OPTIONS 预检失败
→ 跨域来源不在 `app.cors.allowed-origins` 白名单；确认前端地址与之一致。

### Q6：改了模型配置但聊天还是旧模型行为
→ 理论上有 evictCache；若仍异常，重启后端让 `initDefaultClient` 重载默认模型。

### Q7：config.yml 里有真实密钥怎么办？
→ config.yml 是"部署配置"文件（含数据库密码/API Key），**提交 Git 前必须打码或用 .env 注入替代**；本仓库当前是占位符状态。

## 10.5 验证接口的 curl 速查

```bash
# 公开：启用模型列表
curl http://localhost:8080/api/models/enabled

# 登录拿 token
curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"<前端SHA256后的值>"}'

# 带 token 拉用户列表
curl http://localhost:8080/api/admin/users -H "Authorization: <token>"

# 客服 SSE 流式（浏览器地址栏也能看效果）
curl -N "http://localhost:8080/api/chat/stream?message=你好"
```
