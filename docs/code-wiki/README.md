## 5 分钟速览（面试前临时抱佛脚版）

**架构一句话**：标准三层架构（Controller → Service → Repository → MySQL/Redis/Milvus/MinIO），
加上两个特色组件：`ChatClientFactory`（多模型路由）和 `CustomerServiceGraph`（流程编排）。

**6 张表一句话**：
- `ai_model` 存模型配置（聊天时动态切换模型）
- `sys_user` 存用户 + 三个权限布尔字段（极简 RBAC）
- `chat_session` AI 助理的会话
- `chat_message` 所有聊天记录（永久存档）
- `knowledge_base` 知识库文档元数据
- `workflow_graph` 流程编排图 JSON

**5 大核心流程**：
1. 登录：前端 `SHA256(salt+密码)` → 后端 `BCrypt` 校验 → Sa-Token 发 JWT
2. 客服聊天：SSE 流式输出 + Redis 短期记忆（最近 20 条，TTL 24h）+ MySQL 异步落库
3. AI 记忆：Redis List（快、会过期）+ MySQL（慢、永久）
4. RAG：上传文档 → MinIO 存原文件 → 分块 → Embedding → Milvus → 提问时语义检索 Top-K 拼进提示词
5. 多模型：后台配置 baseUrl/apiKey → `ChatClientFactory` 动态构建 + 缓存，无需重启

**2 个面试必考点**：
- 密码**双重哈希**为什么：前端哈希防明文传输（即使 HTTP 被抓包也不知原始密码），后端 BCrypt 防数据库拖库后反推。
- SSE 为什么用 **WebFlux**：`Flux<String>` 响应式流，一个请求不断返回 token 片段，比 WebSocket 更轻量（单向推送够用）。

## 阅读建议

如果你是 Java 小白，第一遍阅读时：

1. 先看 01、02、03 建立整体印象，**不求全部看懂**；
2. 04~07 配合源码对照看（文档里每个类都有源码链接，边看边点开）；
3. 08 的五大流程是骨架，**回看两遍以上**；
4. 最后用 11 的面试题自测，答不上来的题目回到对应章节重看。

> 文档里大量使用「餐厅后厨」「外包团队发货」这类类比帮你建立直觉，
> 面试时**不要**用类比回答面试官，学懂之后要能用 Java 术语复述。
