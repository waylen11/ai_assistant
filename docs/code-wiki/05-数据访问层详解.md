## 5.1 Entity 实体层（6 张表的 Java 影子）

源码目录：[entity/](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/entity/)

公共注解套路（每个实体都这套）：

```java
@Data                          // Lombok：getter/setter/toString
@Entity                        // JPA：这是一个实体类
@Table(name = "ai_model")      // 映射哪张表
public class AiModel {
    @Id                                                     // 主键
    @GeneratedValue(strategy = GenerationType.IDENTITY)     // 自增（交给 MySQL）
    private Long id;
    ...
    @CreationTimestamp  // 插入时自动填当前时间
    @UpdateTimestamp    // 每次更新自动刷新时间
    private LocalDateTime createdAt / updatedAt;
}
```

> 类比：Entity 是"账本表格的模板"，JPA 拿着模板替你干活——
> 你 `save(obj)`，Hibernate 自动翻译成 INSERT/UPDATE，不用手写 SQL。

## 5.3 Repository 仓库层（6 个接口 = 6 个管理员）

源码目录：[repository/](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/repository/)

**Spring Data JPA 的核心魔法**：你只写接口 + 方法名，框架按方法名生成 SQL。

```java
public interface AiModelRepository extends JpaRepository<AiModel, Long> {
    List<AiModel> findByEnabledTrueOrderBySortOrderDesc();          // WHERE enabled=1 ORDER BY sort_order DESC
    boolean existsByModelName(String modelName);                    // SELECT COUNT(*)>0
    AiModel findByModelNameAndEnabledTrue(String modelName);        // AND 条件
    Optional<AiModel> findFirstByEnabledTrueOrderBySortOrderDesc(); // LIMIT 1
}
```

方法名拆解口诀：`find` + `By` + 字段名 + `And/Or` + 条件关键字（`True`/`Containing`）+ `OrderBy` + 字段 + `Desc/Asc`。

各仓库独有方法一览：

| 仓库 | 方法 | 用途 |
|---|---|---|
| AiModelRepository | `findFirstByEnabledTrueOrderBySortOrderDesc` | ★ 启动时取默认模型 |
| SysUserRepository | `findByUsername` / `existsByUsername` | 登录查找 / 建号查重 |
| ChatSessionRepository | `findByUserIdOrderByLastMessageAtDesc` | 侧边栏会话列表 |
| ChatMessageRepository | `findByMemoryIdOrderByCreatedAtAsc` / `countByMemoryId` / `deleteByMemoryId` | 历史查询 |
| KnowledgeBaseRepository | `findByVectorStatus` / `findAllByOrderByCreatedAtDesc` | 状态筛选 / 列表 |
| WorkflowGraphRepository | `findFirstByGraphTypeAndEnabledTrueOrderByVersionDesc` | 取某类型最新启用图 |

> `Optional<AiModel>` 的用法重点：`orElseThrow(() -> new IllegalArgumentException("模型不存在"))`，
> 替代 `if (x == null)` 判空——空值处理的现代姿势。

## 5.4 DTO 层（12 个信封）

源码目录：[dto/](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/dto/)

### 5.4.1 DTO 是什么？为什么要它？

DTO（Data Transfer Object）= 接口专用的数据传输信封。
理想情况下：**输入用 Request DTO，输出用 Response DTO，数据库实体绝不出现在接口里**。

| DTO | 方向 | 说明 |
|---|---|---|
| [LoginRequest](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/dto/LoginRequest.java) | 入 | `@NotBlank` `@Size` 校验注解 |
| [LoginResponse](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/dto/LoginResponse.java) | 出 | token + 用户信息 + 三权限（`@Builder` 构造） |
| [SaltResponse](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/dto/SaltResponse.java) | 出 | 登录前取盐 |

### 5.4.2 面试常问：DTO 和 Entity 有什么区别？为什么分开？

1. **安全**：Entity 的 `password` 字段若直接吐出，等于泄露密码列结构；
   Response DTO 天然不带敏感字段。
2. **解耦**：表结构变了（加字段/改名），接口对外格式可以不变，前端无感。
3. **校验**：`@NotBlank` 等校验注解属于输入信封，不该污染实体。
4. **可塑性**：一个接口可能需要多表数据的组合，DTO 任意拼装。

> ⚠️ 坦白点（面试加分项）：本项目 ModelController/UserController 目前**直接用 Entity 收参/返回**（`@RequestBody SysUser user`），
> 严格说这是 DTO 化的不彻底之处——AuthController 和用户权限类接口已用 DTO 收编，
> 可以说"项目中我意识到了这个问题，正在逐步把实体替换为 DTO"（源码注释里确实有"使用专门的 DTO，不再接受 Map 参数"的演进痕迹）。
