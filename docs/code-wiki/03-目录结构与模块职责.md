## 3.2 每个包的"岗位说明书"

| 包 | 岗位 | 干什么 | 不干什么 |
|----|------|--------|----------|
| `common` | 公司规章制度 | 统一返回格式、异常处理、常量 | 不含任何业务逻辑 |
| `config` | 后勤装配车间 | 造 MinIO 客户端、Redis 模板、向量库、鉴权规则 | 不处理请求 |
| `controller` | 前台接待 | 收 HTTP 请求、参数校验、调 Service、返回 Result | 不写业务 |
| `service` | 业务大脑 | 聊天流程、密码哈希、文档向量化…… | 不写 SQL、不碰 HTTP 细节 |
| `graph` | 调度中心 | 定义并执行"意图→检索→回复"流程图 | 不直接调大模型 API |
| `entity` | 账本表格模板 | 每张表对应一个类，字段=列 | 往接口传参也用它（历史包袱，见 05 章） |
| `repository` | 仓库管理员 | `findByXxx` 方法名即查询 | 只操作对应实体 |
| `dto` | 标准信封 | 接口输入/输出的专用格式 | 不存数据库 |
| `enums` | 合法值清单 | 把"user/assistant"这类字符串固定成枚举 | — |

## 3.4 设计上值得讲的 3 个点

### 3.4.1 启动类的三个注解

```java
@EnableConfigurationProperties  // 让 @ConfigurationProperties 类（CorsProperties）生效
@SpringBootApplication          // 三合一：@Configuration + @EnableAutoConfiguration + @ComponentScan
@EnableAsync                    // 开启 @Async —— ChatService 异步落库、KnowledgeService 异步向量化都靠它
```

- `@SpringBootApplication` 里藏着一个 `@ComponentScan`：自动扫描 `com.huangyuanwei.aics` 包及其子包，
  所以在 `AiCustomerServiceApplication` 所在包之外的类不会被自动注册。
- `@EnableAsync` 是能工作的大前提——**没有它，`@Async` 注解就是哑炮**，这是常见面试追问。

### 3.4.2 配置一分为二：application.yml + config.yml

`application.yml` 用 `spring.config.import: classpath:config.yml` 引入第二份配置。
`config.yml` 存放部署相关的**环境变量式配置**（数据库地址、API Key 等敏感信息），
便于运维改动而不动主配置。**注意：config.yml 里含数据库密码/API Key，提交代码前务必脱敏**（本仓库里已是打码占位）。

### 3.4.3 为什么 chatservice 里 SYSTEM_PROMPT 写在常量里？

ChatService / AssistantService 里各有一大段 `""" ... """` 文本块（Java 17 文本块语法）作为 system 提示词。
它定义了 AI 的人设、服务范围、输出格式（Markdown 表格规范）。
**prompt 也是项目资产**——管理后台换模型不影响人设，人设改这里即可。
