六个依赖 = 这个类干活的全部资源。`@RequiredArgsConstructor` 自动生成构造器做注入（构造器注入是官方推荐姿势）。

### 6.1.2 streamChat —— 九步流水线

```java
public Flux<String> streamChat(String memoryId, String userInput, String modelName)
```

| 步 | 动作 | 代码要点 |
|----|------|---------|
| 0 | 参数校验 | 空值、超 5000 字符、模型名超长 → 抛 `IllegalArgumentException` |
| 1 | 建 `GraphContext` | 塞 memoryId、modelName |
| 2 | 执行流程图 | `customerServiceGraph.execute(userInput, context)`（见 07 章） |
| 3 | 读取 Redis 历史 | `loadHistory(memoryId)` → `List<Message>` |
| 4 | 拼入本轮提问 | `history.add(new UserMessage(userInput))` |
| 5 | 构建客户端 | `buildChatClient(modelName)`（动态切换模型） |
| 6 | 强化系统提示 | `buildEnhancedSystemPrompt(result)`（把检索到的上下文拼进 prompt） |
| 7 | 发起流式请求 | `chatClient.prompt().system(...).messages(history).stream().content()` |
| 8 | 流结束回调 | `doOnComplete`：保存 Redis + **@Async 异步落 MySQL**；`doOnError`：记录日志 |

### 6.1.3 关键方法逐个拆

**① buildEnhancedSystemPrompt —— RAG 的"接线处"**

```java
if (executionResult.getRetrievedContext() != null && !...isBlank()) {
    prompt.append("\n\n根据以下检索到的信息来回答用户问题：\n").append(retrievedContext);
}
```

大模型本身不知道你公司的资料，**把向量库检索回来的相关内容直接塞进 system 提示词**，
模型就"临时拥有了"这份知识——这就是 RAG（检索增强生成）朴素的本质。
（注意：当前 `CustomerServiceGraph.retrieveKnowledge` 是简化空实现，真正的检索能力在 `KnowledgeService.retrieve`，见 6.3 与 08 章。）

**② loadHistory —— Redis 读记忆**

```java
String key = redisPrefix + memoryId;                 // "admin:chat:memory:" + IP
List<String> rawList = stringRedisTemplate.opsForList().range(key, 0, -1);
// 每条是一个 JSON 字符串 {"role":"user","content":"..."} → 反序列化 → UserMessage/AssistantMessage
```

**③ saveToRedis —— 滑动窗口写记忆**

```java
rightPush(key, userJson);     // 尾部追加
rightPush(key, assistantJson);
if (size > maxMessages * 2) { leftPop(key); leftPop(key); }  // 超了 → 头部丢最旧一对
expire(key, Duration.ofHours(ttlHours));                     // 刷新 24h 有效期
```

**滑动窗口**三个要点：上限 20 对（40 条）；超出按"对"淘汰最旧（一问一答成对）；每次写入刷新 TTL。
> 类比：便利店冰柜只能放 40 瓶饮料，新货从后面放，放满了就把最前面最旧的拿出来，且保证"问题+回答"成对下架。

**④ persistMessages —— @Async 异步落 MySQL**

```java
@Async
public void persistMessages(...) { ... chatMessageRepository.save(userMsg); ... save(assistantMsg); }
```

**为什么异步？** 存 MySQL 是慢操作（网络 + 磁盘），如果挡在 SSE 流结束的回调里同步执行，
客户端要等写库完成才算彻底结束。异步化让"回答完成"和"存档"解耦，用户体验优先。
注意其依赖的 `@EnableAsync` 在启动类上（03 章讲过，忘配置就是哑炮）。

### 6.1.4 SYSTEM_PROMPT 设计解读

ChatService 顶部那一大段文本块（Java 17 `"""` 语法）就是客服人设：

- **角色定位**：专业、热情、高效的 AI 客服；
- **服务范围**：产品咨询、在线预约、企业信息、售后支持、投诉建议；
- **输出规范**：强制 Markdown 表格/列表格式（前端 marked 渲染依赖它）；
- **边界处理**：超范围问题转人工、敏感信息不透露、不确定要诚实。

> 面试亮点：**"Prompt 工程也是后端工作的一部分"**。
> 我们把人设、格式规范、边界策略封装成系统提示词常量，通过 `ChatClient.prompt().system(...)` 注入，
> 保证了换任何模型都有统一的客服形象。

## 6.3 KnowledgeService —— RAG 知识库服务

源码：[KnowledgeService.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/service/KnowledgeService.java)

### 6.3.1 uploadAndPreview —— 上传流水线（5 步）

```java
public Map<String, Object> uploadAndPreview(MultipartFile file, Long userId)
```

| 步 | 动作 | 说明 |
|----|------|------|
| 1 | `ensureBucketExists` | 桶不存在则 `makeBucket` 创建（幂等） |
| 2 | 上传 MinIO | 路径 `yyyy/MM/dd/{uuid}.{ext}`（按日期归档+防重名） |
| 3 | 存 KnowledgeBase 记录 | 状态置 `pending` |
| 4 | `splitAndPreview` | 按空行切段 → 过滤 <20 字符的碎段 → 每段截 200 字封装预览（最多 50 条） |
| 5 | `vectorizeAsync(kb.getId(), bytes, name)` | **异步**向量化，立即返回预览给前端 |

> 设计亮点：**同步给预览、异步做向量化**。上传文档要几秒到几十秒，用户先看到分块预览，
> 前端轮询/展示 `vector_status` 的变化，不把请求堵死。

### 6.3.2 vectorizeAsync —— 向量化状态机

```java
@Async
public void vectorizeAsync(Long kbId, byte[] fileBytes, String fileName) {
    // ① status → processing
    // ② new Document(text, Map.of("source", fileName, "kb_id", kbId))  —— 元数据随向量走
    // ③ TokenTextSplitter(chunkSize=500, chunkOverlap=50, ...) 分块
    // ④ vectorStore.add(chunks) —— EmbeddingModel 向量化 + 写入 Milvus
    // ⑤ status → completed + chunkCount + vectorCollection
    // ⑥ catch：status → failed + errorMsg（失败可追溯）
}
```

`TokenTextSplitter(500, 50, 5, 10000, true)` 参数：默认块 500 token、重叠 50 token、
最小块 5、最大块 10000、保留分隔符。

### 6.3.3 retrieve —— 语义检索

```java
public List<Document> retrieve(String query, int topK) {
    return vectorStore.similaritySearch(SearchRequest.builder().query(query).topK(topK).build());
}
```

`similaritySearch`：把 query 也 Embedding 成向量 → Milvus 里按 COSINE 相似度找最像的 topK 个片段。
（配置里 top-k 默认 5。）

> ⚠️ 再次提醒：`milvus.enabled=false` 时这里命中 dummy 空实现、返回空列表。
> 完整 RAG 需开启 Milvus（详见 08 章流程4 与 10 章 FAQ）。

## 6.4 ModelService —— 模型管理 + 缓存失效

源码：[ModelService.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/service/ModelService.java)

| 方法 | 要点 |
|---|---|
| `listEnabled()` | 排序倒序（sortOrder），供前端下拉 |
| `create` | **先查重 modelName**（`existsByModelName`）再存 |
| `update` | 逐字段非空拷贝 + 存库 + **evictCache(旧名/新名)** |
| `delete` | 删库 + evictCache |
| `toggleEnabled` | 翻转 enabled + evictCache |

**本类最重要的知识点：缓存一致性。**

```java
chatClientFactory.evictCache(oldModelName);              // 配置变了，旧客户端作废
if (!oldModelName.equals(saved.getModelName())) {
    chatClientFactory.evictCache(saved.getModelName());  // 改名了，两边都清
}
```

改 apiKey/baseUrl/enabled 后，`clientCache` 里缓存的旧 ChatClient 还是旧凭证——不失效就会用错配置调接口。
"**数据库为准，缓存跟随失效**"是缓存设计的基本功，面试能主动讲。

## 6.5 UserService —— 用户管理 + 双重哈希密码

源码：[UserService.java](../../ai-customer-service-backend/src/main/java/com/huangyuanwei/aics/service/UserService.java)

### 6.5.1 create —— 密码存储方案（面试必考）

```java
String salt = IdUtil.fastSimpleUUID();                          // ① 每用户随机盐
String rawPassword = user.getPassword();
String clientHash = DigestUtil.sha256Hex(salt + rawPassword);   // ② 模拟前端：SHA256(盐+明文)
user.setPassword(BCrypt.hashpw(clientHash));                    // ③ 后端：BCrypt(clientHash)
```

数据库最终存的是 **`BCrypt(SHA256(salt + rawPassword))`** —— 双重哈希：

| 层 | 算法 | 防什么 |
|---|---|---|
| 前端 | SHA256(盐+明文) | 防**传输泄露**：就算 HTTP 被劫持，抓包也只有哈希，拿不到明文（防"泄露=拿到密码"） |
| 后端 | BCrypt | 防**拖库**：即使数据库泄露，SHA256 可被彩虹表/暴力破解，BCrypt 自带 salt+慢哈希+可调成本，难反推 |

**验证时**（AuthController）：`BCrypt.checkpw(前端传来的 clientHash, 库里存的 BCrypt 值)` 一次校验即可。

### 6.5.2 其他方法

| 方法 | 要点 |
|---|---|
| `resetPassword(id, newPassword)` | 校验长度 6~20（用 `AppConstants` 常量）→ 复用/补建盐 → 同 create 流程存储 |
| `assignPermissions(id, model, knowledge, user)` | 三布尔赋值（null → false） |
| `delete / toggleEnabled / update` | 常规；update 只允许改资料类字段（密码必须走 reset 通道） |
