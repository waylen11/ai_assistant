## 12.1 简历项目经历（可直接粘贴版）

**AI 智能客服系统**

- **项目描述**：面向企业客服与内部协同场景的 AI 智能平台，覆盖公开客服智能问答、员工 AI 助理、RAG 知识库问答、多模型动态切换、AI 会话记忆与后台权限管理等完整功能闭环
- **技术栈**：Spring Boot、Spring Data JPA、Spring AI Alibaba、Sa-Token、Redis、MySQL、Maven、Docker

- **多模型动态切换**：模型配置存储在 MySQL 数据库中，聊天时按模型名动态构建 ChatClient，根据是否配置 baseUrl 自动区分阿里云 DashScope（通义千问）与 OpenAI 兼容协议模型（DeepSeek 等），配合本地缓存与配置变更后的缓存失效，实现后台切换模型无需重启
- **流式对话输出**：基于 Spring WebFlux 的 Flux 响应流 + SSE 协议实现 Token 级流式输出，前端"打字机"式渲染，Markdown 表格 / 代码高亮完整展示
- **AI 记忆分层存储**：Redis List 滑动窗口保存最近 20 轮对话作短期上下文（TTL 24 小时、超出自动淘汰最旧记录），回答结束后异步落库 MySQL 作长期归档，兼顾响应速度与数据持久化
- **认证与权限控制**：Sa-Token + JWT 实现登录认证与会话管理，密码采用"前端 SHA256(盐值+密码) + 后端 BCrypt"双重哈希防传输泄露与拖库反推；用户表 3 个布尔字段实现模型 / 知识库 / 用户三模块的细粒度权限
- **RAG 知识库问答**：文档上传 MinIO 对象存储，异步分块 + Embedding 向量化写入 Milvus 向量库，问答时按相似度检索 Top-K 知识片段注入 Prompt，让模型基于企业资料作答；向量化状态以 pending → processing → completed 状态机流转
- **工程规范建设**：统一 Result 响应体与全局异常处理器、ResultCode 枚举与常量类消灭魔法数字；Docker 多阶段构建 + Compose 编排 MySQL/Redis/MinIO/Milvus 等 7 个服务，一键启动

**使用提示**：
1. "项目描述"和"技术栈"两行可按投递岗位微调；
2. 每条加粗标题背熟后，面试时**照着标题讲一句话，再补一个细节数字**（如"20 轮""24 小时""7 个服务"）就很像真做过；
3. 不确定的职责表述（如"独立完成"）不建议加——本项目按"核心后端模块的开发与理解"定位最稳。

## 12.2 面试模拟（按简历每条逐一提问）

> 玩法：先自己口答，再看"参考答法"。全部答完一遍，再回到 [11 章](./11-面试准备与术语表.md) 二刷。

### 通用类

**Q1 面试官：先简单介绍一下这个项目吧。**
参考答法：一句话定位（"一个基于 Spring Boot + Spring AI 的企业级 AI 客服平台"）+ 两种模式（公开客服免登录、内部 AI 助手需登录）+ 挑一条简历点展开一句（建议挑"流式对话"或"AI 记忆"，这两个你最容易讲）。

**Q2 面试官：你在项目里主要负责后端哪些部分？**
参考答法：照着简历六条报，重点说"多模型切换、对话记忆、登录权限"这几个你准备过的；如果被问细了，就说"这块我主要负责理解和使用，部分模块是和资料一起完成的"——诚实但不怯。

**Q3 面试官：前后端怎么对接的？**
参考答法：前端 Vue3 调 REST 接口，统一返回 `{code, message, data}`；聊天接口是特殊的 SSE 流式接口（`text/event-stream`），不是普通 JSON。

### 多模型切换

**Q4 面试官：为什么不把模型写死在配置文件里？**
参考答法：写死的话换模型要改配置 + 重启服务。我们把模型信息（名称、apiKey、baseUrl）存进数据库，后台管理页面上改一下，聊天时动态读出来用就行，不用重启。

**Q5 面试官：通义千问和 DeepSeek 的接入方式有什么不一样？**
参考答法：通义千问走阿里云 DashScope 自己的通道；DeepSeek 这类是 OpenAI 兼容协议，要配它的 baseUrl（如 `https://api.deepseek.com`），后端用 `OpenAiApi` 按 baseUrl 动态构建客户端。

**Q6 面试官：模型配置更新了，缓存里的旧客户端怎么办？**
参考答法：更新 / 删除 / 启停模型的时候，主动把这个模型的缓存删掉（evict），下次再请求时重新构建，保证配置是最新的。

### 流式对话

**Q7 面试官：为什么要做成流式输出？**
参考答法：大模型生成完整回答要几秒甚至更久，流式让它一个字一个字蹦出来（打字机效果），用户不用干等，体验好很多。

**Q8 面试官：SSE 和 WebSocket 有什么区别？为什么选 SSE？**
参考答法：SSE 是单向的（只能服务器推给浏览器），基于普通 HTTP，实现简单；WebSocket 是双向通信但对客服问答来说用不上，所以选更轻的 SSE。

**Q9 面试官：后端用什么实现流式返回的？**
参考答法：Spring WebFlux 的响应式流 `Flux<String>`，大模型每吐一个 token 就是一个元素，接口直接返回 Flux，浏览器持续收到数据。

### AI 记忆

**Q10 面试官：对话记忆存哪里？为什么分 Redis 和 MySQL 两层？**
参考答法：Redis 存最近 20 轮对话，查询快、24 小时自动过期，用来每次拼上下文；MySQL 存全部聊天记录，永久保存。一个当"草稿纸"，一个当"档案室"。

**Q11 面试官：滑动窗口是什么意思？**
参考答法：Redis List 最多存 20 轮（40 条），每轮对话从尾部追加，超过上限就把最旧的一条挤掉，保证上下文不会无限膨胀。

**Q12 面试官：落库为什么要用异步？**
参考答法：写 MySQL 相对慢，放在回答完成后的回调里异步执行，不阻塞客户端收到完整回复。

### 认证与权限

**Q13 面试官：说一下你们密码存储的方案？**
参考答法：双重哈希。前端先 `SHA256(盐值 + 密码)` 再传输，防止中途被截获拿到明文；后端收到后再用 BCrypt 加密存库，防止数据库泄露后被反推出密码。

**Q14 面试官：用户登录之后，后端怎么知道"你是谁"？**
参考答法：登录时后端生成 JWT token 返回给前端，之后每个请求都带这个 token，Sa-Token 拦截器校验通过后，用 `StpUtil.getLoginId` 拿到用户 ID。

**Q15 面试官：三种管理权限（模型 / 知识库 / 用户）怎么实现的？**
参考答法：用户表里直接放三个布尔字段，拦截器对 `/admin/models`、`/admin/knowledge`、`/admin/users` 分别检查对应字段，简单直观，不用建角色表。

### RAG 知识库

**Q16 面试官：RAG 是什么？这个项目为什么需要它？**
参考答法：RAG 是"检索增强生成"——先从知识库检索相关资料，再把资料拼给大模型生成回答。因为大模型不知道我们公司的产品资料，直接问会瞎编。

**Q17 面试官：一份文档上传后发生了什么？**
参考答法：上传后先把原文件存到 MinIO 对象存储，再异步把文本分块、用 Embedding 模型向量化，存进 Milvus 向量库；数据库里记录向量化状态（pending → processing → completed）。

**Q18 面试官：向量是什么？"相似度检索"能通俗解释下吗？**
参考答法：向量就是把一段文字换算成一组数字坐标，意思相近的文字坐标离得近。用户提问也换算成坐标，去向量库里找离得最近的几段（Top-K），就是相关资料。

### 工程化

**Q19 面试官：统一响应体、全局异常处理有什么好处？**
参考答法：前端只要判断 `code` 是不是 200 就行，不用每个接口写一套；异常全走一个地方处理，出错返回友好提示而不是把报错细节甩给用户。

**Q20 面试官：为什么用枚举和常量类，而不是直接写数字和字符串？**
参考答法：避免"魔法数字"。写 `200` 别人不知道什么意思，写 `ResultCode.OK` 一看就懂；而且改一处全局生效，拼错字符串编译期就能发现。
