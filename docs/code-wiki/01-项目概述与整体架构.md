# 01 · 项目概述与整体架构

## 1.1 这个项目是干什么的？

**AI 智能客服系统**：企业把产品资料（PDF/Word/TXT 等）上传到知识库，系统自动"读懂"这些资料；
当客户来提问时，AI 客服先用向量检索从知识库捞出相关资料，再结合大模型（如通义千问、DeepSeek）生成专业回答。

它和"直接调 ChatGPT 接口"的最大区别是三个字：**可落地**。

| 落地能力 | 解决的问题 | 对应技术 |
|----------|-----------|----------|
| 知识库（RAG） | 大模型不知道你公司资料 | 文档分块 + Embedding + Milvus 向量检索 |
| 多模型切换 | 不想绑死一家模型厂商 | ChatClientFactory 动态构建 |
| AI 记忆 | 客服不能"金鱼记忆"，要记住上下文 | Redis 短期 + MySQL 长期 |
| 权限管理 | 谁能管模型？谁能管知识库？ | Sa-Token + JWT + 权限标志位 |
| 流程编排 | 客服应答流程可视化 | Spring AI Alibaba Graph（4 节点图） |
| 流式输出 | 回答像打字一样逐字蹦出来 | SSE + WebFlux |

## 1.2 两种使用模式

| | AI 客服模式 | AI 助理模式 |
|---|---|---|
| 使用者 | 任何访客（无需登录） | 内部员工（需登录） |
| 记忆标识 | 用户 IP | 会话 sessionId（UUID） |
| 会话管理 | 无（只有 IP） | 有（可新建/切换/删除会话） |
| 业务定位 | 产品咨询、售后 | 采购/入库/销售/出库等企业业务 |
| 对应类 | `ChatService` / `ChatController` | `AssistantService` / `AssistantController` |

> 面试官常问："客服模式和助理模式有什么不同？"——答上面这张表就赢了。

## 1.4 分层架构的"交通规则"

```
Controller ───────────调用──────────▶ Service（只能这样）
Service   ───────────调用──────────▶ Repository / 其他工具组件
Repository───────────操作──────────▶ 数据库
```

三条铁律：

1. **Controller 不碰数据库**：它只做"接收请求 → 校验 → 调 Service → 包成统一格式返回"。
2. **Service 写业务**：登录怎么校验密码、聊天怎么拼历史记录、文档怎么分块，全在这里。
3. **Entity 不裸奔**：接口输入/输出优先用 DTO（见 05 章），避免把数据库表结构直接暴露给前端。

> 类比：餐厅里，Controller 是迎宾员（点单、报菜名），Service 是厨师（做菜），
> Repository 是仓库管理员（拿食材），你不能让顾客直接去后厨仓库拿菜——这就是分层。

## 1.5 一次"客服聊天"请求的完整旅行

以「客户发一句"你们的产品多少钱？"」为例，追踪一条请求的一生：

```
① 前端 Vue 发起 GET /api/chat/stream?message=你们的产品多少钱？
        │ （Nginx 反代到后端 8080）
② CorsFilter 放行（跨域握手）
③ SaTokenConfig 拦截器：匹配 /chat/** → 直接放行（公开接口免登录）
④ ChatController.streamChat()
        │ 取出客户端真实 IP 作为 memoryId
⑤ ChatService.streamChat(memoryId, message, modelName)
        ├─ 6a. 输入校验（空值、超长）
        ├─ 6b. CustomerServiceGraph.execute()  —— 关键词识别意图"knowledge"
        ├─ 6c. 从 Redis 读取该 IP 最近 20 条历史消息
        ├─ 6d. buildChatClient(modelName) —— ChatClientFactory 按数据库配置造客户端
        ├─ 6e. system 提示词 + 历史 + 本轮问题 → 大模型 API（stream）
        │        └─ 大模型一个 token 一个 token 往外吐 → Flux 流式返回前端（SSE）
        └─ 6f. 流结束后：写回 Redis（滑动窗口）+ @Async 异步写 MySQL
```

这条链路体现了项目的所有核心点：**免登录接口 + IP 记忆 + 流程编排 + 多模型 + 流式 + 双层记忆**。
