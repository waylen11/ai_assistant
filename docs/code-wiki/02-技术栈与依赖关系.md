### 2.2.1 四个段落分别管什么

```xml
<!-- 段落1：继承 Spring Boot 父项目（统一版本管理，不用自己写版本号） -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.5</version>
</parent>

<!-- 段落2：properties 统一声明版本号（改一处全局生效） -->
<spring-ai.version>1.1.2</spring-ai.version>
<sa-token.version>1.38.0</sa-token.version>
...

<!-- 段落3：dependencyManagement 引入 BOM（物料清单） -->
<!-- spring-ai-bom：Spring AI 家族的版本清单，导入后写依赖不用写版本号 -->

<!-- 段落4：dependencies 真正引入的依赖 -->
```

> 类比：`parent` 是"总公司的统一采购价目表"，`dependencyManagement` 是"AI 部门的子价目表"，
> `dependencies` 才是"我们项目实际下单买的东西"。

### 2.2.2 依赖分组解读

**① Spring Boot 官方五件套**（starter 就是"开箱即用包"）

| 依赖 | 作用 |
|------|------|
| `spring-boot-starter-web` | 传统 Servlet 栈：Tomcat、Spring MVC（普通 REST 接口用这个） |
| `spring-boot-starter-webflux` | 响应式栈：Netty、`Flux`（SSE 流式聊天用这个） |
| `spring-boot-starter-data-jpa` | JPA/Hibernate：实体注解 + 仓储接口自动实现 |
| `spring-boot-starter-data-redis` | Redis：Lettuce 客户端 + `RedisTemplate` |
| `spring-boot-starter-validation` | 参数校验：`@NotBlank`、`@Size` 等注解 |

> ⚠️ 面试冷门点：这个项目**同时引入了 web 和 webflux**。
> 普通接口走 MVC（Tomcat），SSE 接口返回 `Flux<String>` 走 WebFlux 的响应式流。
> Spring Boot 会以 MVC 为主，但 `Flux` 返回值由 WebFlux 的响应式适配器处理。

**② Spring AI 三剑客**

| 依赖 | 在本项目中的角色 |
|------|-----------------|
| `spring-ai-alibaba-starter-dashscope` | 提供 DashScope 的 `ChatClient.Builder`（通义千问通道） |
| `spring-ai-alibaba-graph-core` | 流程编排节点图 API |
| `spring-ai-openai` | 提供 `OpenAiApi` 类，用来动态构建 DeepSeek 等第三方客户端 |

> 关键理解：本项目**不用** Spring AI 的自动配置去固定一个模型，而是用
> `ChatClientFactory`（见 04 章）手动 `new OpenAiApi(...)` 动态造客户端——这就是"多模型热切换"的本质。

**③ 存储三兄弟**

| 依赖 | 作用 |
|------|------|
| `spring-ai-milvus-store` | Spring AI 官方 Milvus 向量库适配（提供 `MilvusVectorStore`） |
| `io.minio:minio:8.5.10` | MinIO Java SDK（上传/下载/桶管理） |
| `mysql-connector-j` | MySQL 驱动（runtime 作用域：只在运行时需要，不打进业务代码） |

**④ 认证与工具**

| 依赖 | 作用 |
|------|------|
| `sa-token-spring-boot3-starter` | Sa-Token 核心 + Spring Boot 3 自动装配 |
| `sa-token-jwt` | 把 Sa-Token 的 token 升级为 JWT 格式 |
| `sa-token-redis-jackson` | Sa-Token 的会话数据存 Redis（分布式/多实例共享登录态） |
| `hutool-all` | 本项目用到：`BCrypt`、`DigestUtil.sha256Hex`、`IdUtil.fastSimpleUUID()` |
| `lombok` | `@Data` `@Slf4j` `@RequiredArgsConstructor` 等 |
| `mapstruct` + `mapstruct-processor` | 编译期注解处理器，自动生成 Bean 转换实现类 |
| `jackson-datatype-jsr310` | 让 Jackson 正确处理 `LocalDateTime` 等新日期类型 |

## 2.4 三个必懂的技术细节

### 2.4.1 Lombok 是什么？为什么 `<optional>true</optional>`？

Lombok 在**编译期**替你生成样板代码：

```java
@Data   // 自动生成 getter/setter/toString/equals/hashCode
@Entity
public class AiModel { ... }
```

`optional=true` 表示"这个依赖只是编译工具，不传递给依赖本项目的其他项目"；
打包时也被 `spring-boot-maven-plugin` 的 excludes 排除出 jar（运行期不需要）。

> 类比你之前学过的理解：外包团队（Lombok）在**发货时**（编译时）帮你把零件装箱
> （生成 getter/setter），货发出后团聚散了也不再露面——jar 里没有 Lombok 也能跑。

### 2.4.2 MapStruct 与注解处理器（annotationProcessorPaths）

`maven-compiler-plugin` 里额外配置了 `annotationProcessorPaths`，
因为 Lombok 和 MapStruct 都是"编译期打工的注解处理器"，必须显式登记它们，
编译器才会在编译时调用它们生成代码。

### 2.4.3 为什么父子工程 + BOM 是主流做法？

- 版本号只出现在 `properties` 一处，升级 Spring AI 时改一个数字；
- `spring-ai-bom` 保证 Spring AI 家族内部各组件版本互相兼容——自己手动配对版本最容易踩坑。
